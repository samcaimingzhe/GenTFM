# GenTFM：論文閱讀筆記與版本規劃

整理日期：2026-10-04  
用途：研究匯報、保留閱讀思路、規劃 GenTFMv1.2／v1.3。  
配套文件：[GenTFMv1.1 → v1.2 AI 修改指南](./GenTFMv1.1_to_v1.2_AI修改指南.md)。

> 本文區分三類資訊：**原文依據**、**目前程式事實／使用者觀察**、**待驗證的改進假設**。使用者口述的名稱已盡量核對；「TTVE」暫對應 TTVAE，仍需與使用者實際閱讀的文章核對。本文是筆記與方案，沒有實作 v1.2，也沒有新增實驗結果。

## 1. 我們真正要解決的問題

給定一個帶標籤的真實 context，生成新的帶標籤行，讓這些合成行作為 TabICL 的 context，提升對真實測試資料 label 的預測能力。

```text
真實 context C = {(x_i, y_i)}
        ↓ GenTFM 條件生成
合成 context G = {(x̃_i, ỹ_i)}
        ↓ 作為 TabICL 的 context
預測真實 X_test 的 label
        ↓
與保留的真實 y_test 比較
```

可以把生成目標寫成：

```text
ỹ ~ p̂(y | C)
x̃ ~ pθ(x | ỹ, C)
```

目前的核心評價應該是 **TabICL 在固定真實測試集上的效用**。分佈相似度、t-SNE／UMAP、類別比例等用來解釋結果，不能替代下游效用評價。

分類任務關心類別可分性和 x–y 關係；回歸任務關心數值 y 的條件關係、範圍、尾部和預測誤差。只有各列邊際分佈相似，仍可能生成對預測沒有幫助的行。

## 2. 閱讀文獻時的總體取捨

GOGGLE、TabDDPM、TabSyn、TVAE／TTVAE、CTAB-GAN 系列、CTVAE 與 Binary Diffusion，主要是針對目標資料集訓練的生成方法；不宜把這些流程一概稱為「對基礎模型微調」。DiffICL 則具有跨資料集預訓練階段，但其推論流程還包含新資料集上的解碼器訓練，詳見下文原文依據。

GenTFM 的方向是借用局部機制，保留以 TabICL prior 訓練的 context encoder、條件 flow matching 和逐行表示。更換成完整圖模型、VAE 或 latent diffusion，會超出目前版本的修改範圍。

| 模型／文章 | 本次重點 | 對 GenTFM 的處理方式 |
|---|---|---|
| GOGGLE | 顯式學習欄位關係圖 | 記錄研究背景，暫不移植圖結構 |
| TabDDPM | 混合型資料處理、y 條件嵌入 | v1.1 已借用 y 條件化思路 |
| TabSyn | 逐欄 tokenization、Transformer VAE | 保留為後續欄位表示研究 |
| TTVAE／TVAE | VGM／MSN 數值編碼 | 支持 v1.3 的數值預處理研究 |
| Binary Diffusion | 類別 ID 的二進位表示 | v1.2 僅借用分類項編碼 |
| CTAB-GAN／CTAB-GAN+ | 多峰、長尾、簡單分佈分別處理 | v1.3 候選預處理政策 |
| CTVAE | y 條件化與對比學習、不平衡資料 | 支持關注 x–y 關係；新損失另做實驗 |
| DiffICL | clean context + noisy query 的條件生成 | 對照現有流程；query 互相注意另作候選實驗 |

## 3. 各篇論文筆記

### 3.1 GOGGLE

**準確名稱：** *GOGGLE: Generative Modelling for Tabular Data by Learning Relational Structure*，ICLR 2023；作者來自劍橋大學等機構。

**原文依據：** 方法同時學習變數之間的關係結構與生成函數，透過圖上的訊息傳遞建模依賴，並能引入關係先驗與正則化。[論文](https://openreview.net/pdf?id=fPVRcJqspu)、[作者官方程式](https://github.com/tennisonliu/GOGGLE)。

**我的閱讀判斷：** 這裡的圖關係值得在匯報中介紹，但目前 GenTFM 沒有顯式欄位圖。直接移植其圖解碼器會改動框架，因此不列入 v1.2／v1.3 的近期工作。可保留「欄位依賴應被模型表達」這個研究問題。

### 3.2 TabDDPM

**準確名稱：** *TabDDPM: Modelling Tabular Data with Diffusion Models*，ICML 2023。

**原文依據：** 數值項使用 quantile transformation，類別項配合 one-hot 表示和 multinomial diffusion；分類 label 可作為條件。官方 MLP 去噪器包含 label embedding，與時間條件及輸入投影融合。論文主要設定中，回歸 target 作為額外數值欄聯合建模；官方網路程式也提供數值條件分支。[論文](https://proceedings.mlr.press/v202/kotelnikov23a/kotelnikov23a.pdf)、[官方 MLP 程式](https://github.com/yandex-research/tab-ddpm/blob/main/tab_ddpm/modules.py)。

**與 v1.1 的關係：** v1.1 使用分類 `Embedding`／數值 MLP 取得 `y_emb`，再與 `x_proj`、`t_emb` 相加。這是借用條件融合思想；v1.1 本身仍使用 flow matching，不是完整復現 TabDDPM。

**使用者觀察：** 加入 y embedding 後，v1.1 的效果比 v1 好。這是目前的實驗觀察；尚未在本筆記提供統一資料集上的分數、種子與統計檢驗，匯報時不能編造提升幅度或因果結論。

**研究假設：** 把 y 從待生成的 x 中分離，可能讓模型更直接學到 `p(x | y, C)`，有利於生成帶有有效監督訊號的 context。

### 3.3 TabSyn

**準確名稱：** *Mixed-Type Tabular Data Synthesis with Score-based Diffusion in Latent Space*，模型名 TabSyn，ICLR 2024。

**原文／官方程式依據：** 數值欄與類別欄先形成各自的 feature tokens，經 Transformer VAE 編碼。官方 tokenizer 在編碼前加入 CLS；準備 diffusion 輸入時移除 CLS latent，再 flatten 其餘 feature latents。不是「先整行投影，再加 CLS」。[論文](https://arxiv.org/abs/2310.09656)、[VAE 程式](https://github.com/amazon-science/tabsyn/blob/main/tabsyn/vae/model.py)、[latent 準備程式](https://github.com/amazon-science/tabsyn/blob/main/tabsyn/latent_utils.py)。

**需要釐清的理解：** 最後 flatten 成一個向量，不代表前面的逐欄 encoder 沒有作用：

```text
目前 GenTFM：整行數值向量 → 行投影 → 行級 context 處理
TabSyn：各欄 token → 欄位間非線性 attention／VAE → feature latents → flatten
```

Flatten 只是排列表示；前面的欄位 attention 已處理欄位交互，通常不能化約成對原始整行做一次線性投影。

**後續研究問題：** 可否只借用「單行內的逐欄 encoder」，將其輸出投影回原有 hidden dimension，再交給 GenTFM？這需要獨立消融，且會改動表示模組，因此不與 v1.2 的兩項改動混在一起。

### 3.4 TTVAE 與 TVAE：避免混淆

口述「TTVE」暫對應 **TTVAE: Transformer-based generative modeling for tabular data generation**，*Artificial Intelligence* 340，2025，104292。原文使用 Transformer VAE，數值欄採 VGM 相關處理、類別欄採 one-hot，並研究 latent interpolation。[出版社原文](https://www.sciencedirect.com/science/article/pii/S0004370225000116)。

**TVAE** 是另一個較早的方法，出現在 2019 年 *Modeling Tabular Data using Conditional GAN* 中，與 CTGAN 共用相關混合型預處理，包含 mode-specific normalization。[2019 原文](https://papers.nips.cc/paper_files/paper/2019/file/254ed7d2de3b23ab10936522dd547b78-Paper.pdf)。

**我的關注點：** 先借用數值欄的可逆預處理思想，而不是替換成 VAE。匯報時應說清楚閱讀的是 TTVAE 還是 TVAE；兩個縮寫不能互換。

### 3.5 Tabular Data Generation using Binary Diffusion

**已由使用者連結確認：** Vitaliy Kinakh、Slava Voloshynovskiy，2024，arXiv:2409.13882v1。

**原文依據：** 類別使用二進位編碼；數值先 min–max normalization，再轉為 32 位浮點的位元表示，串接成行。生成方法使用 XOR 位元翻轉及 BCE，與連續 flow matching 不同。[使用者提供的原文](https://arxiv.org/html/2409.13882v1)、[作者程式](https://github.com/vkinakh/binary-diffusion-tabular)。

**v1.2 的選擇：** 只將分類項從 one-hot 換成類別 ID 的 bits。數值項仍使用現有連續值表示；保留 y embedding、flow matching 和分類輸出 head。

例如每欄最多 12 類時，one-hot 需要 12 維，二進位只需 4 維：

| 類別 ID | 4 位編碼（高位在前） |
|---:|---|
| 0 | `0000` |
| 3 | `0011` |
| 11 | `1011` |

**待驗證假設與代價：** 輸入維度變小，可能改善效率與表徵；但二進位碼的距離會引入人為類別關係，且存在無效碼。不能因為維度下降就預言效用提升。應保留合法類別 logits，再將抽中的類別 ID 編碼回 bits。

### 3.6 CTAB-GAN 與 CTAB-GAN+

**原文依據：** CTAB-GAN 使用 mode-specific normalization 處理多峰數值，並包含長尾資料的對數處理。CTAB-GAN+ 增加 **general transform（GT）**，對部分簡單分佈使用較直接的區間縮放，避免不必要的 VGM 分解。[CTAB-GAN 原文](https://proceedings.mlr.press/v157/zhao21a/zhao21a.pdf)、[CTAB-GAN+ 原文第 4.5 節](https://www.frontiersin.org/journals/big-data/articles/10.3389/fdata.2023.1296508/full)。

**術語校正：**

- **MSN** 是 *mode-specific normalization*，不是 VGM 的對立方案；它通常先用 VGM 找 mode，再表示為 mode 內的標準化數值和 mode indicator。
- **GT** 在此指 *general transform*，不是 Gaussian／quantile transform。典型形式為 `s = 2(x − min)/(max − min) − 1`，另須處理常數欄。
- 「簡單分佈用 GT」的這部分應歸到 **CTAB-GAN+**；「VGM 對所有簡單分佈都不好」則不是可以普遍成立的結論。

**v1.3 的想法：** 對每個數值欄建立可逆轉換政策，根據有限 context 中的分佈診斷，考慮簡單縮放、quantile、log／其他長尾處理、VGM／MSN。資料少時 VGM 可能不穩定，需要明確回退規則。

### 3.7 CTVAE

**已由使用者連結確認：** *CTVAE: Contrastive Tabular Variational Autoencoder for imbalance data*，*Knowledge and Information Systems*，2025。

**原文依據：** CTVAE 將 y 同時作為 encoder 與 decoder 的條件，並加入依 label 組織 latent 表示的對比損失。生成時輸入隨機 latent 與指定 y；主要用於不平衡分類及少數類合成。預處理包括數值 VGM 與類別 one-hot。[使用者提供的原文，第 3 節](https://link.springer.com/article/10.1007/s10115-025-02377-7)。

**我的理解：** 若要控制合成哪些類別、改善少數類表示，y 作為條件很合理。但「能按 y 生成」和「生成資料一定能提高 TabICL 預測」是不同的命題，後者需要我們自己的下游實驗。

**對 GenTFM 的啟發：** 保留 y 條件化，評估條件內分佈與少數類效用。類別重採樣、平衡策略和新的對比損失都會增加實驗變量，先單獨記錄，不納入 v1.2 主實驗。

### 3.8 DiffICL

**準確文章：** *Breaking the Quality–Privacy Tradeoff in Tabular Data Generation via In-Context Learning*，2026 年預印本，arXiv:2605.04911v1。

**原文依據：** 使用凍結的 LimiX encoder，跨資料集預訓練條件 latent diffusion；clean context 用來引導 noisy query 去噪。第 3.1 節明確限制 query 只能注意 context，不能注意其他 query。新資料集推論還需要使用資料集內的 query 資料訓練輕量 feature decoders。[原文第 3 節及附錄 D](https://arxiv.org/html/2605.04911v1)。

**與我們的差異：** GenTFM 直接在混合型行表示上做 flow matching；沒有凍結的 LimiX、逐欄 latent diffusion 或每個新資料集的解碼器訓練。

**必須校正的判斷：** 現有 v1.1 已有「clean context + noisy target/query」訓練流程。因此，加入 query 加噪並不是 v1.2 新增的機制。真正可新增的是明確控制 K／Q 採樣，或測試 noisy query 間的資訊交換。

**使用者提出的候選改動：** 取 200 行 clean context 和 200 行 query，讓 noisy query 也參與 attention 的條件記憶。若允許 query–query attention，這是我們自己的變體，不能在匯報中稱作 DiffICL 的直接復現。

## 4. 目前 v1.1：程式確認與限制

核對基準：[GenTFMv1.1](/Users/caimingzhe/Desktop/new/GenTFMv1.1)。

| 項目 | 目前程式行為 |
|---|---|
| 行表示 | 32 數值槽 + 8×12 one-hot + 32 observed bits，總共 160 維 |
| 分類 y 位置 | TabICL prior 中最後一個有效分類欄；不是固定第 8 槽 |
| 回歸 y 位置 | 第一個數值槽 |
| y 的條件化 | 分類 ID → Embedding；數值 → MLP；加入 query hidden 表示 |
| 訓練拆分 | 行隨機打亂後分 clean context 與 target/query |
| query 加噪 | `x_t = (1−t)x0 + t x1`，學習 `x1−x0` 的 velocity |
| y 保留 | 從 query 的待生成座標中移除；生成完成後填回條件 y |
| attention | query 注意 clean context；目前 query 之間不互相注意 |
| 生成 y | 分類按 context 類別頻率採樣；數值從 context 的 y 重採樣，或接受指定 y |

**需要在匯報中保留的限制：**

1. 目前回歸 prior 將 TabICL SCM 的第一個來源 feature 當數值 target，屬於代理回歸任務，不等於已使用原生回歸 label prior。
2. 數值 y 的 empirical bootstrap 不會主動創造 context 之外的新 y 值。是否需要更平滑的 `p(y | C)`，可另行研究。
3. 目前訓練正規化使用整張 synthetic table 的統計量，生成 wrapper 使用 context 統計量。這是已有的訓練／推論差異；若要修正，應同時修正對照組並明確記錄，避免混成未標明的第三項改動。

## 5. 版本路線

### v1.1：已存在的 y embedding

- 在混合行中識別 y，分開嵌入並作為生成條件。
- 使用者目前回報效果改善；後續在固定評估協議中整理量化結果。

### v1.2：兩項主要候選改動

**A. 分類項二進位編碼。**

- one-hot 改為固定寬度的類別 ID bits，包含 context 裡的分類 y 欄。
- `y_emb` 仍接收類別 ID；數值表示、flow loss 和合法類別輸出 head 延續既有做法。
- 預設 schema 的行寬從 160 降為 96；不表示整個模型參數或計算量同比下降。

**B. 明確的 context/query 採樣與 noisy-query memory 實驗。**

- 先支援 `K=200、Q=200` 的明確、不重疊訓練拆分。
- 保留 `context_only` 作為對照；另提供 `context_plus_noisy_query` 測試 noisy query 參與 K/V 的效果。
- 200 是第一組實驗配置，不應寫死模型張量大小。實際推論只從噪聲生成新 query，不額外取真實測試行當生成條件。
- 保留現有網路模組，修改既有 attention 的記憶內容；這仍改變樣本間的依賴關係，需要獨立比較。

### v1.3：自適應數值預處理

- 根據欄位分佈和 context 數量，選擇簡單縮放、長尾轉換或 VGM／MSN，並提供逆轉換和回退。
- VGM 的 mode indicator 會增加表示維度，需另訂 schema，不能假定直接接上 96 維模型即可。
- 「模型只適合正常分佈」目前是待驗證的直覺。Gaussian 起始噪聲不意味著生成分佈只能是 Gaussian；應先診斷錯誤，再判斷預處理能否改善。

**獨立待研究：** TabSyn 風格的逐欄 encoder、CTVAE 風格的對比損失、平衡 y 採樣。不與上述主改動一次性混合。

## 6. 怎樣判斷改動是否有效

為各候選版本設置相同的評估資料、context／test 切分與 TabICL 配置；本次只記錄評估原則，不安排已有實驗資料的適配工作。

| 層次 | 要回答的問題 | 建議觀察 |
|---|---|---|
| 主要效用 | 合成 context 是否使真實 label 預測更準？ | 固定 TabICL 設定，分類／回歸分開比較原協議分數 |
| 條件品質 | 同一 y 下生成 x 是否合理？ | 分類分組分佈；回歸按 y 區間檢查 x–y 關係 |
| 整體分佈 | 哪些分佈形狀被改善或破壞？ | 邊際分佈、相關性、尾部、多峰、類別頻率 |
| 可視化 | 真實與合成資料在同一投影下如何分佈？ | 相同預處理與投影；區分資料來源，依 label 著色 |
| 計算代價 | 表示縮減是否抵消 query 互動的成本？ | 參數量、記憶體、每步訓練／生成時間 |

**數值 label 也能做 t-SNE／UMAP。** 降維輸入通常用 `X`，回歸 y 用連續色階顯示；若研究聯合 `(X, y)` 幾何，需明示包含 y 並統一尺度。不同來源應在同一投影中比較，不能拿各自獨立擬合的圖直接比較座標。這裡是我們的分析設計，不是上述論文都已驗證的結論。

至少做四組消融：one-hot／binary × context-only／noisy-query memory。四組採用相同 K／Q、prior、訓練預算和評估條件。現有 v1.1 checkpoint 可作歷史參考，但若它的 Q 或訓練量不同，就不能單獨用來歸因第二項改動。

每個候選版本都以自身生成的合成 context 取得下游分數；保留匹配設定的基線，避免把不同訓練配方的差異當成單一模組的效果。

## 7. 匯報時可以採用的敘述

> 我們的目標是根據少量帶標籤 context 生成新的監督樣本，並以 TabICL 在真實測試資料上的效用評價生成品質。文獻提供了三類可參考的局部機制：y 條件化、類別表示壓縮，以及針對數值分佈的可逆預處理。v1.1 已加入 y embedding，初步觀察效果改善。v1.2 計畫比較分類項二進位編碼，並測試 noisy query 參與條件記憶的變體；後者是我們自己的實驗設計。v1.3 再研究分佈自適應的數值預處理。每一步都在相同資料切分和下游預測協議中做消融。

### 匯報前需要補齊

- v1.1 與 v1 的實際分數、checkpoint、配置與種子。
